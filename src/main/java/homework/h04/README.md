Завдання 3: Відкрита дискусія Навіщо в програмуванні окремий тип для «так» і «ні»? Логічний тип boolean (true/false) потрібен для керування ходом програми, перевірки умов у циклах та розгалуженнях if/else, роблячи код зрозумілим та захищеним від помилок. Як сказати !(a && b) людською мовою? «Не правда, що a і b виконуються одночасно» або «Хоча б одне з двох (a або b) є хибним» (за законом Де Моргана це еквівалентно !a || !b). Чим && відрізняється від &? Оператор && є коротким (короткозамкненим): якщо ліва частина false, права навіть не обчислюється. Оператор & завжди обчислює обидва вирази та може використовуватися як побітове «І». Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній? Завдяки короткому обчисленню &&: оскільки x != null повертає false, друга частина x.name == "Іван" взагалі не виконується, тому NullPointerException не виникає. Як запхати 32 відповіді «так/ні» в одне число? Використати 32-бітне ціле число (тип int) як бітову маску, де кожен окремий біт (0 або 1) відповідає за один прапорець (так/ні). Що швидше: n % 2 чи n & 1? Побітова операція n & 1 працює швидше або так само на рівні процесора, оскільки вона напряму перевіряє останній біт числа без виконання математичного ділення.
