1.Навіщо потрібні окремі типи для цілих і дробових чисел?
Вони зберігаються в пам'яті за принципово різними алгоритмами: цілі числа — у прямому чи додатковому двійковому коді, а дробові — у форматі з плаваючою комою (стандарт IEEE 754). Це дозволяє процесору значно оптимізувати швидкість і точність арифметичних операцій.
2.Що означає «рухома кома» і куди вона рухається?
Це означає, що позиція розділової точки (коми) у числі не фіксована жорстко, а може динамічно зсуватися завдяки зберіганню числа у вигляді мантиси та порядку. Це дає змогу ефективно записувати як надзвичайно малі, так і дуже великі числа за допомогою однакової кількості бітів.
3. Скільки цифр після коми комп'ютер здатний запам'ятати?
   Це залежить від розрядності типу даних: тип ⁠float⁠ (одинарна точність) забезпечує точність приблизно до 6–7 значущих десяткових цифр, а тип ⁠double⁠ (подвійна точність) — приблизно до 15–16 цифр. 4.Чому ⁠0.1 + 0.2⁠ не дорівнює ⁠0.3⁠?
   Через те, що багато десяткових дробів неможливо точно записати у двійковій системі числення (вони перетворюються на нескінченні періодичні двійкові дроби). Через обмежену кількість бітів для мантиси виникає мікропохибка округлення.
   5.Чому гроші ніколи не зберігають у ⁠double⁠?
   Через похибки округлення при роботі з числами з плаваючою комою, які з часом накопичуються і можуть призвести до фінансових розбіжностей. Для грошей завжди використовують цілі типи (наприклад, суми в копійках/центах) або спеціальний клас ⁠BigDecimal⁠ в Java.
   6.Чи може число не дорівнювати саме собі?
   Так, може. У стандарті плаваючої коми IEEE 754 існує спеціальне значення ⁠NaN⁠ (Not-a-Number), яке виникає в результаті невизначених математичних операцій (наприклад, ділення нуля на нуль). За специфікацією, будь-яке порівняння ⁠NaN == NaN⁠ завжди повертає ⁠false⁠.
